# 지금 이 프로젝트를 어떻게 이해하면 되는가

## 한 줄 요약

이 프로젝트는 **처음부터 모든 데이터를 다 모델에 넣는 프로젝트가 아니라**,

1. 데이터는 넓게 수집할 수 있지만
2. 실제 공식 파이프라인에서는 핵심 피처(core)부터 먼저 검증하고
3. 이후 확장 피처(extended)를 단계적으로 붙여 성능과 해석을 비교하는 방식

으로 이해하는 것이 가장 맞다.

---

## 현재 기준 파이프라인

현재 팀이 이해해야 할 기본 흐름은 아래다.

1. 데이터 수집
2. 전처리
3. 적재
4. EDA / 모델링 / 평가
5. 확장 피처 추가 여부 판단

즉, 지금 당장은 **1번 데이터 수집 단계의 공식 기준안**만 만드는 중이다.

---

## 헷갈리면 안 되는 포인트

### 1. "수집"과 "모델 투입"은 다르다

데이터를 모았다고 해서 그 데이터를 바로 1차 모델에 전부 넣는 것은 아니다.

- 수집은 넓게 할 수 있다.
- 하지만 공식 기준선 모델에는 핵심 피처부터 넣는다.

### 2. "추가 피처"는 나쁜 게 아니다

원자재, 글로벌 지수, 업황 지표, 뉴스 감성 같은 피처는
무조건 불필요해서 제외하는 것이 아니다.

다만 아래가 필요하다.

- 왜 필요한지 설명 가능해야 함
- 정량 피처로 안정적으로 변환 가능해야 함
- 핵심 피처 대비 추가 효과를 비교할 수 있어야 함

### 3. 처음부터 다 넣으면 오히려 판단이 어려워진다

처음부터 모든 피처를 같은 중요도로 넣으면:

- 어떤 피처가 실제로 효과 있었는지 알기 어렵고
- 수집/정렬/결측치 문제가 한꺼번에 터지고
- 성능이 좋아져도 왜 좋아졌는지 설명하기 어려워진다

그래서 core 기준선이 먼저 필요하다.

---

## 피처 분류 기준

### Core

1차 공식 파이프라인에서 바로 써야 하는 피처

예:

- 삼성전자, SK하이닉스, NVDA 주가
- NASDAQ
- SOX
- VIX
- 미국 기준금리
- USD/KRW
- 공식 macro bundle(`core_macro_features`)

### Extended

핵심 파이프라인이 안정화된 뒤 성능/설명력 개선용으로 붙일 후보

예:

- KOSPI, KOSPI200
- 국내 외국인/기관 순매수 거래대금
- 분기 실적
- NVDA용 미국 알파 피처
- 추가 글로벌 지수
- 업황 보조 지표

### Archive / Reference

당장 모델 입력으로 쓰지 않더라도 참고용으로 보관할 수 있는 데이터

예:

- HTML 페이지 아카이브
- 원문 JSON
- 수동 검토용 외부 소스

---

## 현재 작업의 실제 목표

지금 목표는 다음 둘 중 하나가 아니다.

- 최고의 모델 만들기
- 모든 가능 피처를 완성형으로 정리하기

지금 목표는 아래다.

> 제안서 기준으로 타당한 핵심 피처를 안정적으로 수집하고,
> 이후 전처리/적재/모델링 단계가 공통으로 신뢰할 수 있는 raw 입력을 만든다.

---

## 실무 판단 기준

따라서 앞으로 의사결정은 이렇게 하면 된다.

1. 이 피처는 core인가 extended인가 archive인가?
2. 지금 단계에서 실제 공식 파이프라인에 넣을 대상인가?
3. 현실 세계 의미와 사용 이유를 설명할 수 있는가?
4. 날짜 정렬과 시차 처리가 가능한가?

이 네 질문에 답할 수 있으면, 이후 브랜치 비교나 구현 판단도 훨씬 쉬워진다.
